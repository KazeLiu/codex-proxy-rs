# v3.27.0

## 新功能

- 隐私规则支持按顺序组合多个处理步骤，共享开关与失败回滚边界；工作区和 Desktop 信息预设统一为可编辑的通用规则，支持步骤增删、拖动排序和预览
- 出站代理支持独立启停，停用时保留连接配置和账号绑定，后续请求改为直连，重新启用后恢复代理出口；删除代理时自动解除账号绑定
- 管理端较大的普通 JSON 响应支持 gzip 压缩，减少列表和详情数据的传输量

## 修复与改进

- OpenAI 普通 `503 + error.code=server_error` 在同账号额外重试最多 5 次，耗尽后返回最后一次上游错误；明确容量拒绝仍可在额外重试最多 3 次后按既有规则换号，有效 `Retry-After` 优先
- 同一 Client Key、线程和轮次发生上述“不换号”策略的终态失败后，5 分钟内的同轮次请求跳过该策略的退避重试，避免客户端重试反复消耗同一预算
- 插件中间件等待宿主 `next` 时释放执行名额，返回后继续原调用，减少下游慢请求占满插件执行容量的情况；达到容量或等待上限时返回明确的 503 错误
- 修复首次打开管理端、会话恢复失败时出现空白页的问题，改为显示登录页
- 更新 rustls 及相关依赖，修复已知安全漏洞

## 升级说明

- 从 `v3.26.2` 升级时自动执行合并后的 `0031` 迁移：已有代理默认启用，旧隐私规则逐条转换为单步骤规则，保留开关、顺序和其他设置
- 已通过源码部署执行原 `0031_outbound_proxy_enabled.sql` 或 `0032_privacy_rule_steps.sql` 的数据库与本次合并后的迁移历史不兼容，不能直接升级；请保留备份并先规划数据迁移，不要修改 `_sqlx_migrations` 的 checksum 绕过校验
- 已安装插件的容量仍受其 SDK 配置约束；使用较小上限或未区分 `next` 回调预算的插件，需要由作者调整并重新构建
